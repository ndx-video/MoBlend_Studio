# M0 — Public domains: moblend.dev and lib.moblend.dev

## Summary

User registered moblend.dev (news, info, and docs home for the project) and lib.moblend.dev (official template library). Updated all relevant project documentation (AGENTS, ROADMAP, READMEs, specs overview, PRD 7, PRD 4, API spec, PRD 3, PRD 1, PRD 5, manifest schema, and design prompt) to reflect the new public presence and to position `lib.moblend.dev` as the branded home of the template library (with `moblend-registry` remaining the GitOps backend / CI source of truth during beta and beyond). The schema `$id` was already correctly pointing at moblend.dev; its description was reinforced. Project is still in pre-flight specs/M0 phase; no implementation or config changes.

## Decisions

- Keep `moblend-registry` as the name of the external Git repo / backend (per existing PRD and external-repos convention); the public library is the distinct branded product at `lib.moblend.dev`.
- Beta delivery model (raw Git CDN for artifacts/index) is unchanged; domains provide the user-facing names and future hosting target. Client config in M4 will use library URL (with fallback/raw noted in docs).
- Schema publication path under moblend.dev/schemas/ is confirmed and documented.
- No changes to architecture rules, milestone order, or non-doc files (as expected in pre-flight).
- All references to "registry" as shorthand for PRD 7 content now qualify as "official template library (at lib.moblend.dev)" or "moblend-registry (backing the library)" where it improves clarity.

## Follow-ups

- When M4 work begins, ensure the configured registry/library base URL in Suite Manager, broker cache logic, and any default config examples point at or document `lib.moblend.dev` (or its index endpoint) while still supporting the raw Git URL for the beta phase and self-hosted forks.
- Future PRD 7 or site work (outside this monorepo) will flesh out the actual web presence at the two domains.
- If/when a root README or other top-level marketing blurb is added, surface the two domains prominently.
- Update any future generated client code, default configs, or in-app help text once implementation lands.
