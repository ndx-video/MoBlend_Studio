# M3 — E2E Playwright automation requirement (documentation)

## Summary

Added mandatory documentation requiring use of the newly introduced Playwright E2E suite for all desktop/frontend GUI and React work. This eliminates the manual launch/test/debug loop that had become too time-consuming. The requirement is documented in the desktop README and referenced from AGENTS.md (on-demand) and the progress log (this entry). A new progress file was appended per the immutable rules.

## Changes

- `desktop/README.md`: Added new "Automated E2E Testing (Required for GUI Work)" section at the end. Documents the npm scripts, mocking approach, why it exists, and links to the e2e/ directory and playwright.config.ts.
- `AGENTS.md`: Updated the "Desktop shell" row in the "Where to look" table to include an explicit "On-demand for any frontend/GUI work" pointer to desktop/README.md. Also strengthened the Frontend bullet under Implementation conventions to state the E2E usage requirement.
- `.progress/M003.003.e2e-playwright-documentation.md`: This new append-only file (following .progress/README.md template exactly).

## Decisions

- E2E automation (Playwright + mocks for Wails bindings + broker) is now a required part of the development process for the React UI, not optional.
- Documentation must live in desktop/README.md (the natural place for Wails/frontend devs) and be discoverable from AGENTS.md without cluttering the top-level guide.
- Future agents must treat running `npm run test:e2e` (headless) as part of verifying any change under `desktop/frontend/src/`.
- The existing progress log rules were followed strictly (new file only, correct zero-padded M003.003 name, full template, references to prior M003.002 and PRD 4).

## Follow-ups

- When an agent is asked to work on the Studio UI, navigation, inspector, canvas, Suite Manager, or any React component, the first step must include reading the new E2E section in desktop/README.md.
- Consider adding a pre-commit or CI step that runs the E2E suite in the future (out of scope for this M3 documentation task).
- If real broker-dependent flows need more coverage, the e2e/mocks.ts can be extended or a "full" test project added later.
