# M4d — Gallery UI and Suite Manager

## Summary

Replaced the Home gallery M4 placeholder with live catalog cards from `GET /api/v1/templates`, wired Install → Go `InstallTemplate` → broker `POST /project/load` → editor, and added Suite Manager catalog diagnostics (registry URL, entry count, last fetch, refresh). Closes ROADMAP M4.

## Changes

- `desktop/frontend/src/broker/client.ts` — `CatalogEntry`, `getTemplates()`, `refreshTemplates()`
- `desktop/frontend/src/App.tsx` — Home gallery catalog grid with Install/Open; Suite Manager **Official Template Library** panel; dynamic `window.go` dispatch for `InstallTemplate` / `ListInstalledTemplates` (avoids hung WailsJS binding in Vite-only e2e)
- `desktop/frontend/e2e/fixtures/mocks.ts` — catalog + install mocks, `GET /api/v1/templates` route
- `desktop/frontend/e2e/m4-gallery.spec.ts` — gallery card, install→editor, suite catalog status tests
- `ROADMAP.md` — M4 + M4d marked ✅ Complete; current focus → M5

## Decisions

- Catalog last-fetch time tracked client-side on successful broker fetch (minimal M4d MVP; no new Go binding or broker status endpoint).
- Preview images in e2e use a data-URL to avoid spurious `ERR_NAME_NOT_RESOLVED` console noise during nav sweep.
- `InstallTemplate` / `ListInstalledTemplates` call `window.go.main.App` directly so Playwright mocks work under Vite dev (generated `wailsjs` import hung indefinitely in that environment).
