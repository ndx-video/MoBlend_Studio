# M0 — Specs & Scaffold

## Summary

Completed the M0 scaffold per ROADMAP "Done when" gates. Created the required monorepo directory tree, bootstrapped an empty Wails v2 (React+TS) desktop shell directly under `desktop/`, added a minimal Python package (`pyproject.toml`) + runnable `bootstrap.py` engine stub under `engine/`, and provided `scripts/dev.ps1` (Windows-primary) that invokes the stub via the latest Blender and spawns the Wails dev server (opening the empty desktop window). Used `winget` to ensure latest Blender as requested (already at 5.1.2). All prior M0 work had been docs/spec-only; this is the first implementation landing.

## Changes

- Directory tree created: `engine/`, `desktop/`, `clients/obs/`, `clients/sentinel/`, `scripts/`
- `desktop/`: Wails v2.12 project (react-ts template) initialized and corrected to live directly at `desktop/` (go.mod module `moblend-studio`, frontend/, wails.json, app.go, build scaffolding). `wails dev` launches a working empty shell window.
- `engine/`:
  - `pyproject.toml` (minimal, targets Blender's Python, no external runtime deps)
  - `moblend/__init__.py` (package marker + __version__)
  - `bootstrap.py` (the `--python` entrypoint; prints version, detects bpy, runs cleanly both inside Blender and as a tooling smoke-test)
- `scripts/dev.ps1`: Primary dev launcher. Auto-detects highest-version Blender under `C:\Program Files\Blender Foundation` (or falls back), runs the engine stub, then spawns a new console running `wails dev` (the M0 empty window).
- `clients/obs/README.md` and `clients/sentinel/README.md`: Lightweight placeholders so the required dirs exist, are git-tracked, and self-document their future milestone (M5/M6).
- Blender: `winget upgrade --id BlenderFoundation.Blender ...` executed (result: already at latest 5.1.2; no change needed). Stub verified against `C:\Program Files\Blender Foundation\Blender 5.1\blender.exe`.
- Verification: Direct `blender --python engine/bootstrap.py` succeeded with "bpy available — Blender 5.1.2" + clean exit. `scripts/dev.ps1` executed end-to-end and reported "Wails dev started in separate window."
- `.gitignore` (pre-existing) already covered the new paths (desktop/frontend/node_modules/, build/, *.mo.blend.* shadows, .moblend/, etc.).

## Decisions

- Wails project must be rooted at `desktop/` (not `desktop/moblend-studio/`) to match the monorepo diagram in ROADMAP + PRD 4 + the pre-written .gitignore expectations. Performed a post-init promote of contents + removed the generated subdir + its .gitignore.
- Kept Wails module name `moblend-studio` (clean, matches branding) even though FS dir is `desktop/`.
- `scripts/dev.ps1` (pwsh) because Windows is primary platform. Includes robust Blender discovery so it works with multiple Blender versions installed (common on author machines). The script both proves the stub and literally opens the empty Wails window.
- Engine stub is intentionally tiny and dual-mode (bpy present or not). No scene mutation, no manifest, no server yet — that is M1.
- Added tiny READMEs in the clients/ placeholders: smallest way to make the dirs "real" and useful for future agents without scope creep.
- No root `go.mod` (permitted by ROADMAP: "at repo root (or under desktop/)"); desktop/ is the correct home for the Wails module.
- Winget step performed first per explicit user request; treated as environment prep before code changes.

## Follow-ups

- **M1 (Engine Core)** is next: expand `bootstrap.py` / new modules to load a test `.mo.blend`, implement `set_parameter` (mutating Geometry Node sockets by `socket_identifier`), shadow backup rotation (`.01`–`.05`), and a round-trip test. The stub command line will evolve.
- Update `scripts/dev.ps1` (or introduce `scripts/start-engine`) once the "engine" becomes the long-running FastAPI broker (M2). For M0 the stub is short-lived.
- The stock Wails React template is only the empty shell. Real UI work (Suite Manager, viewport canvas, param grid, timeline) lands in M3; the `specs/stitch-prompt.txt` can be fed then.
- When adding real Python code in M1, consider ruff/mypy config (already stubbed in pyproject) and a small engine README.
- Future cross-platform (Linux/macOS) dev launchers can be added later under scripts/ without disturbing the Windows-first dev.ps1.
- The spawned `wails dev` window + its console can be closed by the user after inspection; it is not a persistent background service yet.
