# M0 — Google Stitch prompt for Studio UI

## Summary

Authored a comprehensive Google Stitch (stitch.withgoogle.com) prompt to generate
the Mo.Blend Studio desktop UI, framed around how a casual user gets quick motion
graphics for broadcast and digital signage. The prompt is derived from PRD 4 and
the specs README, translating the "no-nodes" Canva/CapCut paradigm, live viewport,
dynamic parameter inspector, slot-based timeline, asset drag-drop, and Suite
Manager into a concrete multi-screen design brief. Saved to `specs/stitch-prompt.txt`.

## Changes

- **`specs/stitch-prompt.txt`** (new) — Stitch prompt covering four screens
  (Template Gallery, Editor, Export/Publish modal, Suite Manager) plus a dark
  pro-tool design system and broadcast/signage use-case framing.

## Decisions

- Targeted a **desktop web** layout (wide, multi-panel) rather than mobile, matching
  the Wails + WebView2 shell in PRD 4.
- Encoded PRD 4 §5–6 faithfully: no nodes/keyframes, dynamic parameter grid mapped
  to real control types (text/textarea, color, slider, toggle, dropdown, asset
  drop-zone), slot-block timeline with draggable edges, and a live viewport with
  playback/scrub controls.
- Surfaced broadcast specifics (alpha/transparency for keying, lower thirds,
  tickers, countdown holding screens, score bugs, stingers) and signage specifics
  (menu boards, promo loops, welcome screens, portrait/ultrawide presets, looping
  export) so the generated UI speaks to both audiences.
- This is a design-aid artifact only; it does not commit the implementation to any
  specific generated layout.

## Follow-ups

- Feed the prompt to Stitch; fold the resulting layout into the M3 desktop MVP work.
- Reconcile exported control set against `manifest.schema.json` type enum when the
  real inspector is built.
