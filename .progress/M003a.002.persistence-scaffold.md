# M3a — SQLite persistence scaffold

## Summary

Implemented M3a local persistence: three SQLite databases under `<moblend_home>/` with v1 schemas, migration runners, thin Go/Python wrappers, and minimum log call sites. Recents migrated from `config.json` `recentProjects` into `studio.db` on first Studio open.

## Changes

- `desktop/internal/store/` — `studio.db` + `suite_logs.db` (migrations, recents CRUD, asset index, log append/tail)
- `desktop/internal/moblendlog/` — package-level `Append` helper with swappable backend
- `desktop/app.go` — open/migrate on startup, recents + asset index + lifecycle logging
- `engine/moblend/store.py` — `broker.db` (export_jobs, catalog_cache stub)
- `engine/moblend/log.py` — shared `suite_logs.db` append/tail
- `engine/moblend/server.py` — broker startup migrate, throttled `broker.health`, export job rows
- `engine/moblend/__init__.py` — conditional bpy import for host-Python tests
- `desktop/internal/store/store_test.go`, `engine/tests/m3a_store_test.py`
- `desktop/go.mod` — `modernc.org/sqlite` (pure Go, no CGO)

## Decisions

- Go SQLite driver: `modernc.org/sqlite` for Windows-friendly builds without CGO
- `recentProjects` stripped from `config.json` during one-time import (not rewritten on every add)
- Wails binding surface unchanged (`GetRecentProjects` / `AddRecentProject` still return paths)
- Live-broker E2E (`m3-broker-live`) may fail without a running broker; mocked recents E2E passes

## Follow-ups

- Suite Manager log viewer UI (read via `LogDB.Tail`)
- Optional HTTP log ingest / `moblend-logd` (documented in spec §10, not M3a)
