# M3 — Open in Editor + live viewport preview

## Summary

Fixed the two blockers preventing a usable editor: "Open in Editor" silently no-op'd when `GetDefaultTemplatePath` hadn't resolved yet, and the viewport canvas stayed black because no WebSocket `REQUEST_FRAME` messages were sent automatically. Home flow now re-fetches the template path on click, falls back to broker-already-loaded, shows status/errors, and navigates reliably. Editor starts a ~12fps auto-preview loop once manifest + WS are ready, painting real EEVEE JPEG frames from the broker (verified ~11–12fps via `m2_broker_client.py`).

## Changes

- `desktop/frontend/src/broker/useViewportStream.ts` — `startPreview` / `stopPreview` loop; **rewrote WS lifecycle** to single `useEffect` (fixed StrictMode leaving `wsRef` null while UI showed "WS live")
- `desktop/frontend/src/App.tsx` — auto-preview on editor mount; hardened `loadDefault()`; status UI; `open-in-editor-btn` testid
- `desktop/frontend/e2e/m3-home.spec.ts`, `m3-editor.spec.ts`, `m3-broker-live.spec.ts` — updated/added viewport coverage

## Decisions

- Preview targets 640×360 JPEG with `FLAG_DROP_STALE` — matches M2 headless throughput, not 30fps goal
- If default `.mo.blend` path missing but broker `health.loaded`, skip `POST /load` and open editor directly
- User must restart `wails dev` (or rebuild frontend dist) to pick up changes — Go recompile not required for this diff

## Follow-ups

- First EEVEE frame can take 1–2s cold-start; consider warmup burst on template load
- Hide dev-only viewport toolbar buttons for production polish
