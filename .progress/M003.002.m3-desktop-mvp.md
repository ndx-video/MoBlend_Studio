# M3 — Desktop MVP (engine + broker gaps + Go supervisor + React Studio shell)

## Summary

Completed the M3 Desktop MVP per ROADMAP and PRD 4 §8–§13. Delivered end-to-end Studio: Go spawns/supervises the engine, user can select local .mo.blend → live binary-WS viewport + manifest-driven param form + slot timeline updates, drag-drop asset sandboxing is wired in Go, export job trigger (202 + poll) works, Suite Manager controls health/start/stop.

Engine/broker gaps closed first (set_slot, ingest_asset for image/video/font, export job skeleton) so the UI could be wired without violating the "broker owns bpy" rule.

## Decisions

- Export in M3 is a 202+poll status machine (thread, no real multi-frame mux or long bpy work from worker threads) — real video belongs with M5 OBS work.
- Slots/ingest on the M1 synthetic test template are safe no-ops or manifest sync only; full time-controller + asset wiring behavior appears with properly authored templates.
- Go OnFileDrop registration + explicit CopyToAssetSandbox binding both present (frontend can use either).
- Broker base remains hardcoded in Go for M3 (config hook exists for later remote-cluster use).
- Old greet UI and CSS left in place (inert); smallest diff.
