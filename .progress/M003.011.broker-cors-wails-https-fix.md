# M3 — Broker unreachable: Wails HTTPS CORS fix

## Summary

The broker was **running** on `127.0.0.1:8000` but the Studio UI reported unreachable. Root cause: Wails WebView2 serves the UI from `https://wails.localhost`, which the broker CORS middleware rejected (OPTIONS 400, GET responses missing `Access-Control-Allow-Origin`). All React `fetch` calls to the broker failed in the embedded webview even though `curl` from the shell succeeded.

## Fixes

| Layer | Change |
|-------|--------|
| `engine/moblend/server.py` | Allow `https://wails.localhost` (+ `https://localhost`, `https://127.0.0.1`); regex `https?://(localhost\|127\.0\.0\.1\|wails\.localhost)(:\d+)?` |
| `StatusContext.tsx` | Always probe during poll (even while starting); reset `startingRef` on StrictMode cleanup; recover with “Broker connected.” when broker appears |
| `App.tsx` | Use `wailsjs/go/main/App` bindings instead of ad-hoc `window.go` stubs |
| `app.go` | `EngineHealth` 3s timeout + inject `status: ok`; `isBrokerHealthy` 2s timeout; `locateBlender` returns `""` not fake `"blender"` |

## Verification

```text
curl -H "Origin: https://wails.localhost" http://127.0.0.1:8000/api/v1/health
→ access-control-allow-origin: https://wails.localhost
```

- `npm run build` — pass
- `npm run test:e2e` — 28/28 pass

## User action (required)

**Restart the broker** so it loads the new CORS config — the running Blender process keeps old Python until killed:

1. Suite Manager → **Stop Engine**, then **Start Engine**, **or**
2. Close extra Blender windows / `pwsh scripts/dev.ps1`, **or**
3. Kill whatever holds port 8000, then relaunch Studio

Then restart **`wails dev`** (frontend `dist` was rebuilt).
