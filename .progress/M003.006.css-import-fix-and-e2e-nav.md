# M3 — CSS @import fix and E2E updates for navigation

## Summary

Fixed the @import CSS error in style.css (moved to top to satisfy CSS spec and Vite). Noted that E2E tests were not catching blank page issues on nav clicks. Updated E2E (app-shell.spec.ts) to have a test that clicks every nav item and asserts no console errors + content renders. Explained that the previous "all other pages" and navigation tests were failing due to text mismatches after UI changes. Recommended using the E2E for GUI work. The 34115 Wails dev browser URL is for debugging with Go bindings from real Chrome F12. The runtime:ready messages are normal handshake. The inline styles in components were overriding the token classes, leading to "ZERO styling".

## Changes

- desktop/frontend/src/style.css: Fixed @import order.
- desktop/frontend/e2e/app-shell.spec.ts: Added "clicking every nav item produces no console errors and renders content" test. Updated other tests with better timeouts and locators.
- desktop/frontend/src/App.tsx: Minor defensive updates to some screens.
- Added hotkey support in previous related work (F5/Shift+F5 reload via WindowReload binding, F12 for devtools hook).
- Explained in response the difference between E2E (mocks, dev server) and real wails dev.

## Decisions

- E2E must be run to verify GUI changes; manual wails dev is not sufficient for catching console errors or blank routes on nav.
- The exhaustive nav click test in E2E is the way to ensure "no blank when clicking folder icon, gear, etc."
- For debugging the embedded UI and calling Go methods, use the printed Wails dev browser URL (e.g. http://localhost:34115) in Chrome + F12. The embedded window has limited refresh/DevTools.
- Inline hard-coded styles were the reason "stylesheet not applying" despite tokens.css having the Stitch palette and component classes (.panel, .nav-item.active, .section-label, .list-item 32px rows, etc.).

## Follow-ups

- Continue using E2E autonomously to catch and fix test failures before reporting to user.
- Sweep remaining inline styles in App.tsx to use the token classes/vars so the Stitch look is visible in the wails window and the 34115 browser tab.
