# M1 — Engine Core

## Summary

Completed M1 "Engine Core" per the ROADMAP "Done when" gates. Headless Blender now boots, a test `.mo.blend` is loaded, `engine.set_parameter` mutates manifest-driven Geometry Node interface sockets (by stable `socket_identifier`, all core scalar types), and incremental saves rotate the `.01`–`.05` shadow backups. A fully automated integration script (synthetic template generator + assertions) proves the entire round-trip with no manual Blender UI. The existing `bootstrap.py` entrypoint and `scripts/dev.ps1` were extended so the literal CLI form and the dev launcher both continuously demonstrate the gates.

All work stayed inside `engine/` + one additive change to `scripts/dev.ps1`, exactly as scoped.

## Changes

- New `engine/moblend/io.py`: `shadow_rotate` (the rolling .01–.05 implementation) + `orphans_purge` wrapper.
- New `engine/moblend/manifest.py`: `parse_manifest_from_scene` (now tolerates JSON string or native dict for reliability), `minimal_validate`, `find_parameter`.
- New `engine/moblend/nodes.py`: target resolution (node_groups + materials), identifier-based socket lookup, full coercion table for string/text/int/float/bool/color_rgba/enum, apply + depsgraph flag.
- New `engine/moblend/engine.py`: the three public M1 functions (`load_template`, `set_parameter`, `save_project`) plus tiny module state and helpers (`get_current_manifest`, `is_dirty`).
- Updated `engine/moblend/__init__.py`: re-exports + `__version__ = "0.1.0"`.
- Updated `engine/bootstrap.py`: always forces `use_scripts_auto_execute = False`; added lightweight `--load` / repeatable `--set ID=VAL` / `--save` CLI dispatch so the exact ROADMAP command is a working repro. Falls back to original M0 stub when no demo flags.
- New `engine/tests/m1_roundtrip.py`: self-contained verifier. Procedurally builds a minimal valid GN + modifier + manifest (capturing real `socket_identifier`s), exercises load→set (6 params)→incremental save→reload + live value inspection, asserts shadows and persistence, prints the PASS banner and exits 0/1.
- New `engine/README.md`: quickstart with the three verification commands, package notes, "bpy only" reminder (per M0.011 follow-up request).
- Updated `scripts/dev.ps1`: header/synopsis refreshed for M1; added the `[verify]` block after the stub that calls the roundtrip script using the same `$blenderExe` discovery; final messages updated. Wails spawn behavior unchanged.
- Minor robustness fixes during bring-up (JSON string form for manifest persistence on disk, proper Group Output socket + defensive linking in the synthetic generator to satisfy "node group must have an output socket").

No changes outside `engine/` and `scripts/dev.ps1`. No new runtime dependencies. `.gitignore` already covered the shadow pattern.

## Decisions

- Synthetic (on-the-fly) test template (user choice A during planning) — keeps the repo free of .mo.blend binaries for M1 while the generator code itself documents correct manifest + interface wiring.
- Extended `bootstrap.py` for the demo CLI (user choice) so the ROADMAP literal command string works directly.
- Enhanced `dev.ps1` with the verification step (user choice) — makes the single Windows dev command the continuous proof for M1.
- Exercised **all core scalar types** in the demo/verification (user choice) rather than a single float.
- Added `engine/README.md` (user + M0.011 request).
- Stored the manifest as a JSON string under the custom prop for reliable cross-save/load (with transparent parse support for both str and dict forms). This was a small implementation improvement over the initial "assign native dict" sketch after observing persistence behavior in Blender 5.1; it does not change any public API or observable behavior for callers.
- Shadow rotation implemented with `str(base) + f".NN"` to avoid `Path.with_suffix` compound-extension pitfalls; capped at 5 and drops oldest.
- Kept the public surface strictly to the three functions listed in the Internal Engine API spec for M1; extra helpers are private or convenience only.

## Follow-ups

- M2 (Broker) will consume these functions from the FastAPI layer (via the action queue + bpy.app.timers). The one-shot CLI path in bootstrap can remain for ad-hoc smoke tests or be hidden behind a flag.
- Load-side shadow recovery scan (highest valid .NN when the canonical fails integrity) is described in PRD 2 §2.2 but was out of scope for the M1 gates; implement when the broker needs robust open.
- Real authored templates (from registry / future Template Inspector) can be added as additional test vectors in M4+ without changing the synthetic generator.
- Cross-platform (Linux/macOS) dev scripts can mirror the pwsh verify call later.
- The GN wiring in the synthetic generator is minimal; a richer "looks like a real lower-third" template can be added as a second generator if visual debugging of mutations is desired before M3 viewport work.
