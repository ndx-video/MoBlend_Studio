# M2 — API Broker

## Summary

Completed M2 "API Broker" per the ROADMAP "Done when" gates and the detailed approved plan. Delivered a working FastAPI + uvicorn REST control plane + exact binary WebSocket viewport stream (`ws://127.0.0.1:8000/api/v1/viewport/stream`) running inside headless Blender, using the mandated producer-consumer action queue + `bpy.app.timers` pattern to protect single-threaded bpy.

All work stayed inside `engine/` + one update to `scripts/dev.ps1`, plus the mandatory new append-only progress entry. No desktop, OBS, Sentinel, MCP, or registry changes.

Key demonstrations (all without manual Blender UI):
- `GET /api/v1/manifest`, `PATCH /api/v1/parameters`, `POST /api/v1/project/load` respond correctly (plus `POST /save` and `/health` for practicality).
- Broker boots via `blender ... bootstrap.py -- --serve [--load PATH]`, serves on 127.0.0.1:8000, pre-loads a template when requested.
- `scripts/dev.ps1` now auto-detects Blender's python, pip-installs the runtime deps into it (idempotent + verification), launches the serve in a bg window (pre-loading the M1 synthetic), and prints the client instructions.
- `render_frame` (new public engine API) produces JPEG/WebP bytes via Eevee at client-requested resolution.
- CORS allows `http://wails.localhost` + dev localhost origins.
- Stale frame drop and bounded queue + 429 logic implemented (exercised in client code + HTML tester; observed in runs).
- Two verification artifacts: automated host Python client (`m2_broker_client.py`) and zero-dep browser canvas tester (`m2_viewport_tester.html`).

The M1 roundtrip continues to pass on every `dev.ps1` run (no regression). All architecture rules from AGENTS.md respected.

## Decisions

- Used `threading.Event` + mutable result/exc box for the web→timer bridge (simpler and less error-prone than cross-thread `asyncio.Future` + `loop.call_soon_threadsafe`).
- Tempfile + `bpy.ops.render.render(write_still=True)` + magic-number light check for `render_frame` (no Pillow or other imaging deps — keeps "minimal" rule).
- `--serve --load` support (user-approved in planning; huge ergonomics win for repros and `dev.ps1`).
- Endpoint surface: exactly the ROADMAP three + `POST /save` + `/health` + `/templates` stub (user choice "minimal + practical"). render/export etc. return proper 501 error envelope.
- `/templates` is a deliberate stub returning `[]` with a comment; full cached `index.json` fetch is M4.
- Both verification clients (user choice) — the Python one for automated gate proof, the HTML one for visual + manual fps/scrub debugging before M3 canvas work.
- Auto pip + verification in `dev.ps1` (user choice) using the probed Blender python + a post-install Blender --python-expr check. Added runtime sys.path injection in bootstrap as defense-in-depth for Windows embedded Python quirks (observed during bring-up).
- Stale drop implemented both at enqueue (latest tracking) and consumer; client/HTML explicitly exercise the flag.
- Kept the original M1 one-shot CLI and `m1_roundtrip.py` 100% working and still executed first by `dev.ps1`.
