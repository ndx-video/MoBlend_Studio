# M3 — GUI initiative: no-blank nav, auto default template, smart broker attach + pre-load

## Summary

Took proactive initiative on real user pain points reported for the Studio GUI:

- Navigation to several left-toolbar pages produced blank/minimal results. Fixed by replacing all remaining Stubs with proper (if M3-limited) screens and giving Editor a prominent "Load default" experience.
- Users had to manually hunt for the test .mo.blend on every launch. Go now auto-loads the well-known M1 synthetic (m1_minimal_test.mo.blend) after the broker is healthy. Frontend also exposes a one-click path.
- Broker startup was naive (could produce port-in-use errors, didn't attach to previous instances). StartEngine now always probes first; if a healthy broker is already present it attaches and skips spawn.
- Essential broker services + initial template load now happen as part of the Go-side engine startup sequence (before or during the time the React GUI becomes interactive). A non-blocking readiness banner was added.

These changes were implemented without waiting for further user prompting.

## Changes

- `desktop/app.go`:
  - Added `isBrokerHealthy()` fast probe.
  - Rewrote `StartEngine` to probe first → attach/reuse if healthy (solves "port already in use").
  - Track `ownedEngine` so Stop only kills processes we started.
  - Added `defaultTemplatePath()`, `maybeAutoLoadDefault()`, `loadViaBroker()`.
  - `StartEngine` (and the auto-start in `startup`) now calls the default load after the broker reports healthy.
  - New public binding `GetDefaultTemplatePath()`.
- `desktop/frontend/src/App.tsx`:
  - Replaced the three remaining `Stub` components with real (M3-appropriate) screens: `AssetsScreen`, `ExportScreen`, `UserSettingsScreen` — all render visible, explanatory content.
  - Added a rich "No template loaded" panel inside the Editor parameter area with a "Load default test template" button that uses the new Go binding + loadProject.
  - Added a global non-intrusive top banner (next to nav rail) that says "Broker starting / connecting…" until `EngineHealth` reports ready. This gives immediate feedback on essential service status.
  - Updated `useGoBindings` shim with `GetDefaultTemplatePath`.
  - Ensured every route always produces visible, non-blank content inside the AppShell.
- Minor: data-testid already present from prior E2E work continue to help.

## Decisions

- Broker "pre-load" and default template loading is best done in Go (during/after StartEngine) because Go owns the spawn lifecycle and can talk to the broker over HTTP without the frontend being ready.
- Probing the broker health endpoint before any spawn is the cleanest way to support "attach to existing" (dev.ps1, previous crash, etc.) and eliminate port-in-use errors for normal users.
- We still surface the Start/Stop controls in Suite Manager for advanced control and diagnostics; the auto-magic just makes the default experience delightful.
- No blank pages on nav is now an invariant: every screen must render at least a title + helpful text or controls.

## Follow-ups

- The Go-side auto-load of the default template means that when the React Editor mounts (after navigation or on direct /editor), `getManifest` / the auto `loadCurrent` effect will usually already see data.
- If a user runs `wails dev` while a broker from `scripts/dev.ps1` is still alive, we now attach instead of fighting over the port.
- Future: persist the last successfully loaded template path (beyond just recents) and prefer it over the synthetic M1 test file for returning users.
